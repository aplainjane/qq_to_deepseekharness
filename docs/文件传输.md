# 管理员 QQ 文件传输

仅适用于已配置 ownerQQ、dsh.ownerTools=true 的管理员私聊，不开放群文件上传下载。单文件最大 20 MiB。

## 用法

- 管理员在 QQ 私聊中发送文件，桥接接收 `file` 消息段或 `offline_file` 通知后，向网关查询该文件下载地址，再保存至管理员工作区的 `QQ收件箱/`，向助手投递路径、大小及名称。文件内容是不可信数据，不自动执行，等管理员说明用途。
- 请助手“把某个工作区文件发给我”。管理员助手使用本地命令：
  `node scripts/send-owner-file.mjs <文件路径> [管理员QQ] [显示文件名]`
  命令从 qq-bridge 目录运行；多个管理员时必须指定 QQ。相对文件路径按管理员工作区解析，而不是命令工作目录。
- 文件发送工具刻意不注册到群聊共用的 snowluma-safe MCP：普通会话即使知道管理员 QQ，也没有无令牌上传本机文件的工具入口。管理员通过已有完整本地工具调用脚本，不需要刷新 DSH MCP 工具列表。

## 安全限制

- HTTP 接口 `POST /api/owner/send-file` 必须有控制台令牌，不接受任何 x-agent-token 请求；同时检查管理员身份、当前模式白名单及 deny 列表。
- 发送只允许工作区内真实路径下的普通文件，禁止 URL、目录、越界路径、符号链接越界、配置文件、私钥、.env、内部 state/.git/.dsh/.ssh/node_modules 路径；这不是通用 DLP，管理员仍需确认产物不含敏感内容。
- 接收只使用文件事件的 ID 调用 `get_private_file_url`，不使用用户输入的任意 URL；下载沿用 DNS/IP 与每跳重定向安全检查，拒绝内网地址；网关返回内网下载地址时会失败关闭。
- 文件名去路径、过滤特殊字符，随机前缀且禁止覆盖。接收文件只落地不解压、不执行。
- 网关接口为 `upload_private_file`、`get_private_file_url`；真实投递和下载仍受 QQ/网关支持、账号权限和网络影响。上传 API 成功不等于对方客户端已下载。
